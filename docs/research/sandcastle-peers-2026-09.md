# Is sandcastle alive, and what are its real peers (Sept 2026)

Research note for [issue #3](https://github.com/chizhangucb/software-factory/issues/3). Date: 2026-09-06. Primary sources only; every claim links to the thing that owns it.

## TL;DR

- `mattpocock/sandcastle` is not archived, but it has been silent from its only maintainer since 2026-06-29. Zero merged PRs, zero maintainer comments, and 12 untriaged spam issues since then. Treat it as unmaintained until Matt says otherwise.
- The two "ralph" runners the ticket names are both stalled: `frankbria/ralph-claude-code` last touched 2026-07-10, `snarktank/ralph` dormant since 2026-02-02.
- The runners with real 2026 traction are `fabro-sh/fabro`, `mikeyobrien/ralph-orchestrator`, `umputun/ralphex`, `AnandChowdhary/continuous-claude`, and Vercel's `eve-software-factory-template`. Only the last two turn a GitHub issue or PR into a merged or draft PR unattended.
- Nothing surveyed, open source or productized, reads GitHub's native blocked-by issue dependencies. Only `ralph-claude-code` parses `blocked by #N` from issue bodies, and it is stalled.
- On billing: a Pro/Max OAuth token is documented as supported inside the `claude` binary and `claude-code-action`. Anthropic's legal page says third-party products and Agent SDK builds must use API keys. The June 15 "Agent SDK credit pool" change was paused.

## 5. Can a Claude Pro/Max OAuth token be used, and where

- Sanctioned surfaces: `claude setup-token` "for CI pipelines, scripts, or other environments where interactive browser login isn't available... authenticates with your Claude subscription and requires a Pro, Max, Team, or Enterprise plan" ([authentication](https://code.claude.com/docs/en/authentication#generate-a-long-lived-token)). GitHub Actions doc: "`CLAUDE_CODE_OAUTH_TOKEN`: an OAuth token that authenticates with your Claude subscription, available on Pro, Max, Team, and Enterprise plans" ([doc](https://code.claude.com/docs/en/github-actions#manual-setup)). The action's own setup doc says "Pro and Max users can generate this by running `claude setup-token` locally" ([setup.md](https://github.com/anthropics/claude-code-action/blob/main/docs/setup.md)).
- The restriction, exact wording from [legal and compliance](https://code.claude.com/docs/en/legal-and-compliance): "OAuth authentication is intended exclusively for purchasers of Claude Free, Pro, Max, Team, and Enterprise subscription plans and is designed to support ordinary use of Claude Code and other native Anthropic applications." And: "Developers building products or services that interact with Claude's capabilities, including those using the Agent SDK, should use API key authentication through Claude Console or a supported cloud provider. Anthropic does not permit third-party developers to offer Claude.ai login into their own applications, or to route requests through Free, Pro, or Max plan credentials on behalf of their users." Plus "Anthropic reserves the right to take measures to enforce these restrictions and may do so without prior notice."
- Agent SDK overview: "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK" ([overview](https://code.claude.com/docs/en/agent-sdk/overview)).
- Support article, the softer personal-use line: "Anthropic may at its discretion allow paid subscribers who have enabled usage credits to use certain third-party tools to access Anthropic services included in paid subscription plans, but reserves the right to draw use of such third-party tools from usage credits rather than subscription limits." Prohibited: tools that "misrepresent their identity to Anthropic's servers, attempt to route third-party traffic against subscription limits" ([logging in](https://support.claude.com/en/articles/13189465-logging-in-to-your-claude-account)).
- The June 15, 2026 Agent SDK credit pool (Pro $20, Max 5x $100, Max 20x $200 per month, covering `claude -p`, the Agent SDK, GitHub Actions, and "third-party apps that authenticate with your Claude subscription through the Agent SDK") now carries the note "The changes described below were paused as of June 15, 2026" ([article](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)). Paused, not withdrawn.
- Consumer Terms have no Claude Code clause; the relevant line bars automated access "Except when you are accessing our Services via an Anthropic API Key or where we otherwise explicitly permit it" ([terms](https://www.anthropic.com/legal/consumer-terms)).
- Net: no page says verbatim "only inside the CLI or the official action". The operative wording is "ordinary use of Claude Code and other native Anthropic applications" plus the API-key requirement for third-party products and SDK builds. Running the unmodified `claude` binary or `claude-code-action` in your own CI on your own token is documented. A harness that spawns `claude -p` (sandcastle, both ralphs, ralphex, continuous-claude) is gray: not a product offering login to others, but a third-party tool routing traffic against subscription limits, which the support article says Anthropic may bill to usage credits at its discretion.

Per-option verdict on a Pro/Max token:

| Option | Pro/Max OAuth token |
|---|---|
| claude-code-action | Documented and supported |
| sandcastle, ralph-claude-code, snarktank/ralph, ralphex, continuous-claude, ralph-orchestrator, fabro, machinist | Technically works via `claude -p` or CLI login; not a sanctioned surface, subject to discretionary usage-credit billing or blocking |
| Copilot cloud agent, Codex cloud, Cursor cloud agents | Not applicable; their own billing, no Claude token input |

## Recommendation for the factory

- Do not build on `@ai-hero/sandcastle` as a dependency. Pin 0.12.0 if it is already in use, vendor or fork the pieces you need (worktree manager, sandbox providers), and stop expecting upstream fixes. Reassess only if Matt commits again.
- Keep the shape sandcastle dogfoods: label-triggered GitHub Action, `agent:*` label state machine, separate review workflow. That pattern is repo-owned and survives the library going quiet.
- Use `anthropics/claude-code-action` as the execution layer if the factory runs on a Claude Max token. It is the one surface where subscription billing in CI is documented, it has `label_trigger`, and it releases daily. Accept that it will not merge, wait on checks, or read issue dependencies; the factory owns those.
- Own the orchestration bits nothing ships: a scheduler that reads GitHub native blocked-by via `gh issue` dependencies (available since 2026-06-10), required-check gating, and GitHub-native auto-merge with branch protection as the merge gate. `continuous-claude` is the only OSS reference for the checks-then-merge loop; read it, do not depend on it (4 commits in 90 days).
- If the factory is meant to run without a Claude subscription in the loop, the closest turnkey fit is Copilot cloud agent (assign issue, sandbox validation, review approvals now count) or the Vercel eve template (label `factory`, draft PR with an independent reviewer). Both stop short of merge by design.
- Budget for policy drift: the Agent SDK credit pool is paused, not cancelled. Design the runner so the auth path can flip from OAuth token to API key with one secret change.
